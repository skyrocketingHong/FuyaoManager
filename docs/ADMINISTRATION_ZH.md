# 用户管理、操作日志和管理台外观

平台首页的“平台设置”分组提供用户管理、操作日志和外观设置。用户管理和操作日志只对平台管理员开放；服务端同时校验完整会话与平台角色，写请求还校验 Origin 和 CSRF。普通成员可以使用自己的账号设置和管理台外观设置。

## 账号和授权

新增用户会创建普通成员账号，并返回一个十分钟有效、只能兑换一次的验证码。验证码仅在当前对话框显示，关闭后清除；未使用的旧码会在重新签发时失效。新账号兑换后先绑定当前域名的通行密钥，再进入管理台。已经绑定的账号可以通过新签发的码恢复登录。

在用户的“管理”抽屉中可以修改用户名及显示名称、调整平台角色、启用或停用账号、删除账号、逐站授权、查看和撤销有效会话、撤销通行密钥。

| 范围 | 角色                   | 权限                                                   |
| ---- | ---------------------- | ------------------------------------------------------ |
| 平台 | 平台管理员             | 管理账号、站点授权和审计记录                           |
| 平台 | 普通成员               | 使用已获站点权限的业务功能                             |
| 站点 | 所有者、编辑者、查看者 | 沿用各站点接口既有权限；平台角色变更不自动改写站点角色 |

系统在事务内保护最后一名正常管理员和每个站点的最后一名正常所有者。当前账号不能停用或删除自身；已删除账号不能恢复。停用会使会话、未使用验证码及待完成仪式失效，重新启用不会恢复旧凭据。删除保留账号历史、站点内容和业务发布。撤销通行密钥会同时撤销该账号的登录产物；不能撤销自己在当前域名下的最后一把密钥。会话详情显示完整或受限范围、最后访问、过期时间及当前会话标记，不将“有效会话”表述为实时在线状态。

账号生命周期和站点授权共用事务锁；通行密钥登录在会话签发时重新锁定并核对实际凭据，防止已撤销凭据的迟到验证重新产生会话。这些边界覆盖 ASVS 8.2.1、8.2.2、8.3.1、7.4.1 和 7.4.2。

## 操作日志

详情记录目标用户名、角色与状态及站点授权的变更前后值、具体撤销的会话或密钥 ID；这些值由写事务提供规范值，历史记录缺失的详情不会补造（迁移 0015）。

审计记录从迁移 0014 部署后开始积累，不补造历史。可按操作人、操作类型、结果、时间范围或关键词检索并分页，展开查看事件 ID、账号 ID、接口模板、站点 ID 和连接地址。连接地址记录实际网络对端，不信任转发请求头；经过反向代理时可能显示代理地址。

记录包括认证操作、管理及业务写入和被拒绝的请求。筛选切换时主动取消的只读查询不作为失败操作。账号管理变更与成功审计记录同事务提交；其他请求按 HTTP 结果记录，持久化失败会写入服务日志。字段采用固定白名单，不记录验证码、Cookie、CSRF 令牌、请求体、原始查询字符串或凭据字节（ASVS 16.2.1、16.2.5、16.3.1、16.3.2）。用户详情也仅提供密钥与会话元数据。

管理 HTTP 只提供审计读取接口。数据保存在 PostgreSQL 并沿用数据库备份流程；本轮未配置外部集中审计归档。构建任务的详细输出仍从构建页面读取。

## 管理台外观

“外观设置”提供日间、夜间、跟随系统、12 种预设颜色、自定义颜色和恢复默认。选择即时应用到管理台组件和 CSS 变量，在当前浏览器保存；系统模式会随系统变化，其他标签页也会同步。同样可以从账号菜单进入；顶栏日夜快捷按钮保留当前强调色。错误、告警等状态颜色独立于强调色，自定义颜色会按实际底色校正文字对比度。

接口定义以 [管理 OpenAPI](../contracts/openapi/openapi.yaml) 为准，通用界面复用来源见 [UI_REFERENCE_ZH.md](./UI_REFERENCE_ZH.md)。部署保持业务发布隔离；账号授权和外观修改不会应用 Caddy 或切换运行中的网站。

## 静态产物管理

同时具有平台管理员权限和站点所有者身份的账号，可以在「构建」和「发布」中删除单个或选中的静态产物。删除构建产物会关闭该构建的后续预览和发布入口，已经发布的副本照常服务。删除历史发布产物会失去该版本的回滚入口。操作保留构建与发布记录，可按可用、待清理或已删除筛选。

平台在删除前检查整批条目。当前发布、边缘仍在使用的历史发布和活动预览均受保护。关闭相关预览或完成边缘配置同步后，可以重新选择条目。如果删除中断，记录会显示「待清理」，可在原记录上重试。

## 从 GitHub 安装主题

在服务配置中设置 `FUYAO_ADMIN_THEME_SOURCES`。每项使用 GitHub 公共仓库的 HTTPS 链接、主题 ID、分支和仓库内的主题目录。例如 FuyaoHomepage 使用以下配置。

```sh
FUYAO_ADMIN_THEME_SOURCES='[{"id":"fuyao-homepage","url":"https://github.com/skyrocketingHong/FuyaoHomepage","branch":"main","path":"site"}]'
```

服务重载后，平台管理员可在「主题目录 → GitHub 来源」检查更新并安装。平台校验主题清单、配置契约及 npm 锁文件，按检查时的提交下载，在独立目录内准备依赖并登记版本。站点进入「主题选择」即可选中该版本，按原有构建、预览和发布流程验证。已登记的同版本保留原来源。安装期间的进度由运行进程维护，服务重启后可重新检查已登记版本并重试。

服务端需提供 Git、Node.js 22 或更高版本及 npm，并能访问 GitHub 和 npm 公共注册表。构建会以服务账号运行主题脚本，运维应登记有发布信任关系的仓库。
