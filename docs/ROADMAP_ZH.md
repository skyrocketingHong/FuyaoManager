# 内容管理平台路线图（MVP 迭代台账）

[English](./ROADMAP.md) | 简体中文

内容管理平台的敏捷台账。每个工作包交付可运行、已验证的增量；未实现并验证的能力不列为已完成。2026-11-11 起"后续"部分围绕已批准的主题化与 React 迁移轨道（T1 至 T5）重构；其后的功能包保持原有范围。

## 已完成

1. **后端 MVP（本地开发）**（`admin/backend`）：PostgreSQL + SQL migrations、仅 Passkey 的 WebAuthn 认证（可发现凭据、强制 UV）、CLI（`migrate`、`serve`、`bootstrap-admin`、`create-site`）、带 CSRF/Origin 校验的 Cookie 会话、事务化 ETag 并发的站点列表/详情/配置。仅回环监听。契约：`contracts/openapi/management.yaml`。
2. **加固轮**：事务化首次登记闭环（咨询锁，并发完成仅一者成功）、verify 时点重检许可有效期、完整 ETag 的 If-Match 绑定（拒绝通配）、会话内稳定 CSRF 令牌（多标签页可用）、verify 路径请求体限额与单对象 JSON、TTL 配置错误显式失败、CORS 暴露 ETag。
3. **管理前端 MVP**（`admin/frontend`）：登记、登录/注销、站点列表/详情/配置（dirty 字段提交、412 冲突恢复、viewer 只读）；由契约生成的 API 类型与漂移检查；中英文 Crossfade；日夜主题；同源开发代理拓扑（5174 端口固定、仅回环）。非浏览器的协议联调（后端 serve + 开发代理 + Cookie/Origin 流程）已在本包验证中覆盖；真实平台认证器仪式与视觉验收仍由用户执行。
4. **T1 —— 主题契约 v1**（`contracts/theme/`）：主题清单（`theme.json`）、构建输入快照元数据（`input.json`）与发布元数据（`release.json`）的机器可校验契约，全部为 JSON Schema draft 2020-12，配套公开安全的正负例 fixture，覆盖版本、路径穿越、能力、URL 约定、摘要与未知字段拒绝。可消费的校验与契约同步落地：Go 包 `admin/backend/internal/themecontract`（schema 编译、主题配置交叉校验、清单与输入配对、能力与 URL 约定缺口计算）以及 `fuyao-admin validate-theme` CLI。预留标识：首个主题 `fuyao-homepage`，首个受信任适配器 `node22-sveltekit-static`。契约文档：`contracts/theme/README_ZH.md`。经 `go test ./internal/themecontract/ ./internal/cli/`、`go vet`、`gofmt`、`go build`、prettier 与仓库隐私审计验证。
5. **T2 —— 首个主题注册**（`site/` 注册为 `fuyao-homepage`）：`site/theme.json` 与 `site/theme.config.schema.json` 与契约 fixture 一致；`prepare-build-inputs.js` 写入 `private/input.json`（主题 id/版本与 `version.json` 绑定，不一致即中止构建）并计算三项输入摘要——公开内容树附加内容路径/媒体映射、站点配置、主题配置；`public-config.json` 更名 `site-config.json` 覆盖全部真实消费方（`vite.config.ts`、build-context、`generate-blog-index.js`、`prepare-content-release.js`）。`--frozen=<snapshot>`（或 `FUYAO_FROZEN_INPUT`）为 T3 提供最小消费入口：冻结快照只读校验（身份、协议、摘要冲突一律拒绝），仅其可写构建资产镜像进入 SvelteKit。共享逻辑位于 `site/scripts/lib/theme-input.js`。经 `fuyao-admin validate-theme` 校验 `site/`、svelte-check、99 项站点测试（含 4 项新增 theme-input 测试）、lint、完整构建与改动前基线的归一化产物对比验证：250/250 个文件、99 个非哈希路径全部一致，其余差异仅为 `__BUILD_TIME__`/`__sveltekit_` 派生的资产哈希重命名与构建时刻字段。
6. **T3-a —— 后端主题登记与逐站选择**（`admin/backend`）：migration 0003 新增 `themes` 目录表与 `site_theme_selections`；操作员驱动的 `fuyao-admin register-theme` CLI 是唯一登记入口（HTTP 接口不接受路径、命令或 Git 地址），登记前按 `contracts/theme` 校验主题根、强制受信任适配器列表、将 source 解析为被校验根目录的绝对真实路径，并存储清单、SHA-256 摘要与配置 schema；重复登记只有在完整身份（摘要与 schema，含声明/未声明之分）一致时幂等。HTTP 面：`GET /api/v1/themes` 与 `GET/PUT /api/v1/sites/{siteId}/theme`，沿用既有成员权限、CSRF、Origin、If-Match 模型，修订号计数独立（`-t` 标签，`t0` 表示未选择）；`themeConfig` 省略按 `{}` 处理，显式 `null` 拒绝；非法配置返回不含路径的 422；未设置 `FUYAO_ADMIN_THEME_CONTRACTS` 时保存返回 503 而非跳过校验。OpenAPI 同步更新，类型生成、漂移与语义检查全绿。面向任务 PostgreSQL 18 实例验证：完整 `go test ./...` 加 gofmt/vet/build，覆盖目录读取、持久化、权限、过期 ETag、并发首次保存与登记冲突回归；证据存于 `.fuyao/theme-migration/verification/t3a/`。

7. **T3-b1 —— 真实快照构建与私有预览闭环**（`admin/backend` + `site/`）：migration 0004 持久化按站点构建任务，创建事务冻结确切版本视图（站点设置快照与修订、主题选择修订、主题身份与配置）；执行器角色为集群级 advisory lock——仅持有者把中断的 `running` 行标记失败并重新入队 `queued`，且持有角色直到 worker 排空，第二实例不会误杀第一实例的活跃任务。执行器所有阶段绑定注册主题根，执行前按登记身份复核磁盘 `theme.json` 与配置 schema 摘要（发现注册后被篡改的源码），构建前用受信任服务端站点需求检查主题 capabilities/URL conventions（缺失项明确失败），以主题自身 Node 流程准备快照并注入数据库保存的站点设置（`site.name/description/defaultLocale`，description 经 `site.site.description` 进入公开 SEO 元数据）与主题配置（JSON 文件），随后以**复制+校验+冻结**把快照与产物固化到任务独立目录。工作区隔离返修后，所有写入步骤都在任务私有的注册主题源副本内完成（`taskDir/theme`，排除 node_modules 与可变构建状态，依赖按仓库树向上解析复用，契约 schema 经 `FUYAO_THEME_CONTRACTS` 绝对路径注入），注册源——含其 `.fuyao` 状态与 `build/`——全程零写入、不移走、不恢复；每个任务记录逐文件源码清单（聚合摘要与文件数，migration 0005），覆盖范围宽于 theme.json 摘要。命令在净化环境与独立进程组中运行（取消时组级终止），不继承数据库连接串或管理密钥；这是环境与进程卫生，不是 OS 级沙箱。预览：每个成功构建获得独立回环 origin（按构建监听），入口一次性令牌换取 HttpOnly cookie——根绝对资源、深层路由、声明的 SPA fallback 均保持生产行为，不同构建/站点绝不串产物，origin 与管理 API 不同源，主题脚本无法读取管理响应。HTTP 面：`POST/GET /api/v1/sites/{siteId}/builds`、`GET .../builds/{buildId}`、`POST .../builds/{buildId}/preview-links`，沿用既有成员/CSRF/Origin 模型；OpenAPI 与生成类型同次更新。已在任务 PostgreSQL 实例验证：闭环测试经 API 创建两个真实任务并真实执行 Node/SvelteKit 构建后走预览 HTTP 面（数据库设置冻结进快照、摘要入库、产物只读、第二构建 origin 只服务自身内容、跨 origin 令牌与匿名访问被拒），另含能力缺口构建的持久化明确失败；后端全量、site 受影响配置/主题输入测试、OpenAPI 漂移检查与 prettier 通过。证据存于 `.fuyao/theme-migration/verification/t3b1/`。

8. **T3-b2 —— 发布与回滚闭环**（`admin/backend`）：migration 0006 新增 `site_releases`（冻结主题身份、三输入摘要、routes、reasons、live/superseded/failed 状态与失败记录）与 `sites.current_release_id` 指针；migration 0007 将唯一性改为仅约束生效发布（live/superseded），失败尝试保留历史且同一构建可重试，重复发布已发布构建返回 409 冲突。`internal/publish` 执行器复检受信站点需求（能力与 URL 约定缺口精确入失败记录）、核对清单 `requiredArtifacts`、生成并按 `release.schema.json` 校验 `release.json` 后以复制+校验+冻结固化进 `ReleasesRoot/<site>/<buildID>`，再于按站点发布 advisory lock 的事务内读取基础状态、原子切换指针；任一阶段失败持久化失败发布记录且原发布保持生效，部分固化目录自动清理。回滚直接复用既有产物重新指向（不重建、不动未发布编辑），对已生效/失败/产物缺失目标拒绝。发布以每次尝试独立暂存目录固化产物，在发布锁内原子移入最终目录，失败清理只触及本尝试暂存、结果不确定时不删除可能已激活的产物。发布 origin 为按站点回环监听、按请求解析当前 release，发布/回滚即时切换内容且与管理面不同源；发布记录可经 `GET .../releases/{releaseId}` 查询。HTTP 面：`POST/GET /api/v1/sites/{siteId}/releases`、`GET .../release`（当前发布+origin URL）、`POST .../releases/{releaseId}/rollback`，owner/editor 写、成员读；OpenAPI（含 Release/ReleaseCreate/ReleaseFailure schema 与新 Problem 码）、类型生成与路由↔操作覆盖核对同次更新（21 项操作全对齐）。经真实 Node/SvelteKit 构建验证：发布→冻结 release.json→origin 服务内容→未发布设置修改→二次发布切换→live/superseded 历史→回滚恢复且编辑保留→409/404/403 边界，以及 requiredArtifacts 缺失发布 422 精确缺失清单、原发布保持生效、失败记录入史、失败目标不可回滚；后端全量 `go test ./...` 通过。证据存于 `.fuyao/theme-migration/verification/t3b2/`。

9. **T4 —— 管理前端迁移 React + TypeScript + Vite + 官方 Ant Design**（`admin/frontend`）：React 18 + react-router 7 + antd 5（ConfigProvider 双语 locale 与日/夜 algorithm）+ Simple Icons（GitHub 品牌图标），`admin/frontend` 内不再有 Svelte 运行时。保留 Passkey 登记/登录/注销与会话处理、5174 固定端口同源代理拓扑（WebAuthn origin 不变）、站点列表/详情/配置编辑的 dirty 字段提交、If-Match/412 冲突恢复、viewer 只读、乱序防护与按站点 keyed 状态（业务模块移植为框架无关存储 + `useSyncExternalStore`）；中英字典扩展、日夜主题切换 antd 算法、`prefers-reduced-motion` 收敛全部动画（含 antd 的）。新增主题选择（目录+JSON 配置+If-Match+412 同步）、构建任务（创建、排队/运行轮询、失败记录、私有预览链接）与发布页（当前发布+origin、历史、发布、确认回滚）。`pages/` 与路由层级对应，`lib/` 业务模块不含 JSX，生成 schema.d.ts 类型经同一 OpenAPI 链路消费（api:check 绿）。`npm run admin:check && npm run admin:test && npm run admin:build` 全部通过（25 项测试：client 6、i18n 3、编辑状态机 8、主题选择 5、挂载视图 3）。证据存于 `.fuyao/theme-migration/verification/t4/`。

10. **T5 —— 联调与本地预览交付**：任务 PostgreSQL 实例上独立开发库（与集成测试库分离）、migrate、serve、React 管理台开发服务器与首主题注册全部就绪，向用户交付访问 URL、首次初始化步骤（bootstrap-admin 许可→UI 登记 Passkey→create-site→选主题→构建→预览→发布→回滚）与准确停止方式；真实平台认证器仪式与视觉验收按约定保留给用户。

11. **N1 —— 应用外壳、CLI 首次绑定、一次性码登录、网页建站**（`admin/backend` + `admin/frontend`）：migration 0008 新增 `auth_codes`（SHA-256 摘要存储、`init`/`login` 用途绑定、80 位随机码、尝试消耗、24 小时清理），migration 0009 新增站点 `visibility`（默认私有）与 `provision_state`/`provision_failure`。CLI 新增 `fuyao-admin init-admin`、`login-code`、`revoke-sessions`。`POST /api/v1/auth/exchange` 事务化兑换——码消费、用途校验、登记咨询锁内的首位管理员激活与会话创建同事务提交，并发兑换只可能一者成功；端点带按地址内存限速；每次登录签发全新会话。`GET /api/v1/session` 报告 `platformInitialized`，未初始化浏览器看到准确 CLI 指引而非空表单。`POST /api/v1/sites` 从网页建站（slug/主题/可见性校验，可选初始主题选择按主题 PUT 同标准校验）并在 `FUYAO_ADMIN_SITES_ROOT` 下供应按站点内容/配置树与明确状态——数据库成功不等于建站就绪——另有幂等的 `POST .../provision` 重试。React 管理台新增桌面外壳（平台/站点两级分组侧栏与当前站点上下文、含页面标题与账号操作的固定顶栏、antd 圆角令牌 4/8/12）、带初始化指引的登录码页面、含供应状态列与重试的网页建站向导，并移除 Passkey UI（`@simplewebauthn/browser` 依赖移除；后端 Passkey 端点与数据保留，文档明确其仅适用于域名 RP ID——IP 部署下返回 `503 passkey_unavailable` 且服务正常启动）。新增环境变量：`FUYAO_ADMIN_TRUSTED_HOSTS`、`FUYAO_ADMIN_AUTH_CODE_TTL`、`FUYAO_ADMIN_SITES_ROOT`、`FUYAO_ADMIN_UI_DIR`（带 CSP 与 SPA fallback 的控制台静态托管）。OpenAPI、生成类型与路由覆盖表同次更新（25 项操作）。已验证：后端全量绿（新增测试：初始化流程含平台探测与重用拒绝、登录流程含并发单胜兑换、用途分离、过期与问题码稳定、建站含磁盘供应、重复 slug 409、成员隔离、幂等供应重试），前端 check/test/build 绿（35 项测试），以及从空库开始的真实二进制冒烟——migrate → init-admin → 未初始化探测 → 兑换 → 建站（`provisionState=ready`、目录落盘、托管 UI 200）→ 退出 401 → 重放 409 → 新登录码 → 再登录可见站点 → revoke-sessions。证据存于 `.fuyao/cms-n/verification/n1/`。

12. **N2 —— 受控 Caddy 联动、预览关闭与远程入口、目标服务器首次私网部署**（`admin/backend` + `admin/frontend` + `deploy/fuyao-admin/`）：migration 0010 新增 `site_network_entries`——统一运维批准端口范围、跨用途唯一、每站点一个边缘入口、每构建一个预览入口，分配前试绑定并按竞态重试。预览 origin 按配置地址绑定并使用平台分配端口；签发 URL 携带外部基址（绝不暴露绑定地址）；`POST .../builds/{buildId}/preview-close` 幂等地撤销令牌、停止监听并释放端口。`internal/edge` 管理器从数据库状态渲染受管 Caddy 片段（私有入口只绑定私网地址、公开入口绑定全部接口），在发布/回滚时原子切换按站点 `current` 指针，启动与可见性变更时修复漂移，经固定运维命令（`sudo -n /usr/local/sbin/fuyao-caddy-apply`）应用，校验/reload 失败时恢复上一份有效片段；`PUT .../visibility` 重新绑定站点，`GET .../release` 优先返回边缘入口 URL。部署暴露并修复的真实问题：受信主机的明文 HTTP 不再给 Cookie 加 `Secure`（否则浏览器静默丢会话）、`NODE_OPTIONS` 可透传净化后的构建环境（2 GB 主机堆调优）、发布站点根目录允许反向代理用户穿透。已部署 149.129.75.59（Tailscale 100.117.154.115）：本机 PostgreSQL 18、低权限 `fuyao-admin` systemd 服务（cgroup 内存上限、新增 2G 磁盘 swap）、Go API 托管构建后控制台、主题源码包 + `npm ci` 依赖、运维 Caddyfile 一次性 import 受管片段目录。已从外部客户端经 Tailscale 端到端验证：未初始化探测 → init-admin → 兑换 → 建站（目录落盘）→ 服务器真实主题构建成功 → 预览 `http://100.117.154.115:20000`（令牌交换 303、页面 200）→ 关闭（204、旧链接拒连、端口释放、幂等）→ 发布（live、`edge applied`）→ 私有站点经 Caddy 于 Tailscale 200；公网探测 8787/20000 无任何可用入口（被既有 tproxy 拦截，已用不经 VPS 出口的外部网络验证）。后端全量与前端 check/test/build 绿；新增集成测试覆盖预览分配/外部基址/关闭/重开与边缘发布/可见性/一致性修复/应用失败恢复。证据：`.fuyao/cms-n/verification/n2/`；部署模板见 `deploy/fuyao-admin/`（双语 README、systemd 单元、配置样例、apply 脚本）。
