# Console design and implementation references

FuyaoManager uses the robot platform's desktop shell: a sidebar with 208px expanded, 52px icon-rail and hidden modes, an operation bar and an independently scrolling workspace. The sidebar presents the brand, current scope, fixed entry points, grouped navigation and footer. The icon rail keeps icons and group titles of up to two lines, and every entry keeps its accessible name. Hovering the rail or focusing one of its controls floats the complete menu over the workspace without moving the page; Escape dismisses it, and it returns once the pointer leaves or focus enters again. The hidden mode restores from the left end of the operation bar, which shows the brand mark while the rail is shown. The mode is saved per browser. Filters, tabs and primary actions sit in the operation bar. The version control on the right opens the running service version and commit; the bubble has no arrow, and its surface morphs from the capsule's size to the details' size over 420ms, and back when it closes. From a 720px container the operation bar is a single row: navigation on the left and the session controls on the right stay in place, and the page area between them (leading, filters, tabs and actions) scrolls sideways; a vertical wheel or trackpad scroll moves it, and the edge that still hides content fades. Below 720px it becomes two rows, with navigation and the session on the first and the page area wrapping on the second. Narrow screens use a navigation drawer. A page change cross-fades, with the outgoing page fading out over 100ms and the incoming one easing in over 200ms; a change that only touches tabs or filters, a replace navigation, reduced motion or a browser without the View Transition API switches instantly. The sign-in and passkey pages carry a continuous aurora: two ribbons of light loop on a canvas over a sky gradient for 7.2 seconds and fade out toward the bottom. The aurora can be paused; it stays still and offers no control when the system asks to reduce motion.

Ant Design tokens and CSS variables share the console's theme, with motion durations of 100, 200 and 300 ms (`--motion-fast`, `--motion-mid`, `--motion-slow`); the 420ms morph of the top bar's version bubble is the exception the robot platform sets for capsule surfaces. Inputs and selects are 34px high from 992px and keep 44px below that. Panel borders and surface colors set the hierarchy. Forms and records can use 8:4 or 6:6 columns in wide containers and follow natural document flow on narrow ones; form grids have at most two columns with a 20px gap. Standalone lists use `TablePanel` and `DataTable`, with sticky headers and room for long values. Tables that scroll horizontally expose a named, keyboard-focusable region. The workspace and table content areas fade only at an edge that hides content, and drop the fade under forced colors. Status tags carry five semantics (success, warning, danger, info and neutral) with colors independent of the accent; the tint and border mix into the surface behind them. Tags wrap, and stay on one line inside table cells. Loading states announce "Loading" by default. Versions and identifiers use monospace text. Field labels and the consequences of destructive actions stay visible. Display settings offer a personal content background: 90% of the theme background mixed with 10% of the chosen color.

Paths identify primary pages and site scopes. Query parameters identify tabs and shareable filters. New subviews update the address through `PageTabs` and `usePageQuery`. Back, forward, reload and login restore the selected view. The UI keeps draft confirmations, one-time actions and bulk selections in local state. In-app navigation is protected by the react-router blocker; signing out first asks the active draft guards through `lib/editing/leaveGuard` and clears the session only once leaving is confirmed. Article editing and tables retain their existing components and styles. Categories, tags and media use `?tab=`, with redirects for previous links.

Each route slot is wrapped by `PageBoundary`. A page that fails to render reports the error inside the workspace with a retry, while the sidebar, operation bar and session stay mounted; the failure clears when the location changes.

`App.tsx` and `lib/navigation` own page entry points. Feature code lives in `pages/` and the corresponding `features/`. Tables, panels, version controls and operation-bar slots belong in `components/`. Relative imports point only at the same or a lower layer: `lib`, `components`, `features` and `pages` depend upwards in that order, the entry files are unrestricted, and a component that composes pages belongs in `pages/`. `tests/boundaries.test.ts` checks the import direction and that the page registry in `App.tsx` covers every navigation item. `withPageTransitions` turns the page change transition on once at the router entry (`main.tsx`), so no navigate call or link passes `viewTransition`; it applies to forward navigations that change the path and to the matching back and forward trips. The entry point uses `StyleProvider layer` to give shared styles and component tokens explicit cascade precedence. Site permissions, sessions, date preferences and static publishing follow FuyaoManager's own contracts.

## Adaptation boundary

The sync baseline is commit `7ddbaf0e` (2026-11-24) on the robot platform's `dev` branch, reviewed through `487d109e` of the same day: the only interface change in between is the login page's aurora motion (`b336dd75`, ported); the rest covers the separate frontend and backend releases, edge host maintenance and device firmware. The following belongs to device business, product key visuals or platform infrastructure and is not ported: the 5×3 workbench grid and cards, the cockpit, device and driver pages with the sandbox runtime, the `ContentSurface` background slot, the Kubai icon engine, device status and quick capsules with their effects, the presentation login page's robot imagery, stars and pointer spotlight, modular packaging and standalone release artifacts. FuyaoManager's own content motion (albums, friend reordering) and the narrow-screen navigation drawer keep their existing implementations.

One place is narrowed to this console: the robot platform keeps its operation bar to a single row at every width. This console's session controls include an account button and need about 225px at minimum; on a narrow screen a single row would leave about 100px for the page area, so containers below 720px keep the two-row layout of 2026-11-14 (`6d7b8fa`, `8e001d3`).
